\begin{abstract}
\noindent
This report describes a complete FPGA matrix-multiplication accelerator for the DU-PCB-001-003 card
(Kintex-7 480T, PCIe Gen2, two DDR3 channels): the hardware, the software around it, the build flow and the
design-space exploration (DSE) that tuned it. A host program sends \(A\) and \(B\) over PCIe DMA into the two DDR3
channels; an HLS kernel adapted from \code{gemm\_hls}~\cite{gemmhls} computes \(C = A\cdot B\) in float32; the host
reads \(C\) back together with cycle and memory-stall counters. Everything is built from one JSON file by a Python
flow (HLS, LiteX, Vivado, host tools), and a DSE driver builds, loads and benchmarks whole grids of configurations
unattended, writing traceable JSONL/CSV results.

Twelve campaigns (20 Vivado builds, 206 verified run rows) took the kernel from \gflops{23.4} to
\textbf{\gflops{110.9}} at \(8192^3\), \SI{96.2}{\percent} of the \gflops{115.2} peak of a 32\x8 processing-element
array at \SI{225}{MHz}. The steps that mattered were sending \(A\) transposed (the kernel read \(A\) one word at a
time), larger memory tiles (until BRAM ran out) and a higher clock that only Vivado's \code{explore}/\code{aggressive}
presets closed. Host transfers run at \SI{0.82}{GB/s} (host to card) and \SI{1.49}{GB/s} (card to host); at
\(8192^3\) the kernel is \SI{92}{\percent} of the end-to-end time.

A second exploration added integer and fixed-point element formats without changing the kernel's source: the flow
generates the element type, the host packs and checks the data exactly, and thirteen more campaigns (33 builds) sized
the arrays the freed DSPs allow. int8 reaches \SI{426.6}{GOP/s} (PE 32\x32, \SI{225}{MHz}) and int4
\textbf{\SI{1370.9}{GOP/s}} (PE 64\x64, \SI{180}{MHz}, 38 DSPs), 12.4 times the float32 result. Exact checks
also found DDR3 read errors under load, fixed by tuning the read delays under load at bring-up, and two tile rules
that the upstream kernel assumes but does not check.
\end{abstract}
